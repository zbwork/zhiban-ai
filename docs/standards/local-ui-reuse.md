# 本地模式 UI 复用规范

悬浮提示沿用Flutter Tooltip及AppTheme统一主题：显式设置对称上下内边距、文字行高与均匀行间留白，避免桌面紧凑默认尺寸下路径文字贴底。不通过单个业务入口偏移文字或新增提示组件修正。

本地模式与服务端模式共享同一展示组件、布局参数与交互入口。本地适配仅替换数据和操作回调，不能用近似的 Material 默认控件替换产品 Tab、菜单、筛选栏或空态。

创建/编辑表单同样适用：必须复用 CreateAgentDialog/CreateAgentEditor 的完整字段与校验，注入本地保存/头像/技能能力适配。账号依赖字段保留入口并解释使用条件，不触发远端 Provider；不能只保留名称/提示词后称为原版。可编辑字段必须存储、重开回显，并验证在卡片/会话中的实际用途。

App 内的纯展示组件需要跨入口使用时，提取至 zhiban-client，旧文件 export 共享实现；共享包禁止反向 import App。提供本地数据时必须跳过原远程 Provider 的初始化、watch 和刷新。

空态应根据可用视口居中；在滚动容器中需提供最小视口高度。验证要覆盖无数据和搜索无匹配两种情况，不能只验证文案存在。

用户要求保留原设计时，必须复用整个既有业务组件，而非仅借用卡片再重排页面。数字员工目录和技能安装弹框通过可选本地目录/回调注入；传入本地数据时不得初始化远端 Provider。原组件的无参/默认服务端分支保持行为不变。验收检查组件类型与完整操作链，不能仅检查文案。

本地聊天附件必须复用 RichPromptController/ChatSessionView 的附件块与原 AttachmentPreviewHost。Host 跨入口使用时移到共享包，旧桌面路径 export，同一个实现；回调必须使用预览 Scope 内的 context。异步验证未通过不能清空输入；仅消息写入本地成功才清空。附件保存与解析属于 service/controller，不新增产品 UI 组件。

禁止把原组件的权限/删除只读标志当作临时 busy 开关：composerEnabled 只表示会话是否可编辑；请求状态使用 isSending，文件解析使用 sendReady。附件解析和模型请求期间必须保持原 PromptInput State 挂载。FutureBuilder 不得在每次 build 无条件创建数据库查询 Future。

技能安装复用原 SkillInstallAgentDialog 的 busy/成功/失败状态；先完成包校验与本地事务，再绑定员工，成功才显示“使用”。目录版本和安装版本分别保存，刷新目录不得覆盖已验证指令。每轮只复制摘要验证通过的文件到员工私有技能目录，挂载只读，安装不运行脚本。

原安装弹框通过可选 localPackageHealthy 状态区分绑定与可用性；损坏包复用同一按钮样式显示“重新安装”，修复完成后显示“使用”。不新增平行恢复弹框。


定时任务使用原 TaskPage/TaskEditorContent 与本地 Service 适配；员工列表、打开会话、状态变化通过能力参数注入。社区表单禁止初始化远端模板。Riverpod 局部覆盖 Service 时，依赖的 Notifier 必须声明 dependencies，确保状态归属同一作用域；异步刷新后检查 ref.mounted。运行记录更新通过本地事件刷新，不增加页面轮询。


本地员工并发控制必须由控制器统一执行所有者令牌；聊天、任务认领与删除共用，业务入口不能只靠 busy 预检查。任务取锁早于数据库认领，执行者只接受当前员工令牌；取消与释放分别处理，避免旧请求释放新请求的锁。
