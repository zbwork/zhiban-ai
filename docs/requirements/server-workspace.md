# 可选服务器工作区（第一阶段）

## 客户端优先修复（2026-11-12）

暂停完整后台扩展，先验收本地工作区、连接/登录、员工聊天及附件、返回本地后的数据与凭据隔离。当前源码实测 /message-files/upload 与 /chat/media 为 404；复用上游附件 HTTP 处理器、ChatUploadSvc/ChatMediaSvc、原存储和会话权限，不创建数据库或迁移。上游与社区共用抽出的 HTTP 包，不另写附件业务。原 multipart/presign/confirm、JSON 签名地址及 302 协议保持。

行业最佳实践与适配性：沿用已调研的 Flutter 数据源隔离与 [OWASP 逐请求授权](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) 原则；adopt 原服务的账号/租户/会话成员校验，adapt 仅分离公共 HTTP 依赖；reject 客户端直连 Admin、公开对象存储或伪造上传成功。验收使用当前源码产物、真实 Flutter 上传/下载逐字节核对、SDK 消息/历史及匿名/跨租户拒绝，不能用旧部署测试替代。

保留既有本地 SQLite、模型 Key、技能、定时任务和工作区切换流程；只修已复现的客户端阻断项。服务端真实付费模型、本机工具及原生点击须分别记录实际验证情况。后台仅在客户端稳定后按必需管理能力另行收敛。

职位选项沿用上游租户字典读取，注册 /agents/positions 显式路由，避免被员工详情 /agents/{uuid} 捕获返回 500；不补字典或权限种子。模型选择仍按原社区能力标志关闭，不将商业成员模型目录替换为虚构静态列表。

通讯录打开人际单聊、创建群和读取群成员复用原 directroom/room 服务、原 HTTP 处理器和 WuKong provisioner。成员可见性、同租户、群创建人数及邀请规则不变；客户端消息仍走 SDK，不新增群列表协议或管理功能。验收包含真实成员/员工建群、群详情、成员权限、SDK 发送确认及非成员拒绝。

部署保留检查发现旧服务能装配当前服务器技能，而源码一律下发关闭标志，导致编辑入口消失。接回原能力判定和技能 DTO，列表/详情/保存后回读一致；仍由原技能服务验证创建者和可用性。公共技能目录仍只浏览，不恢复公共安装；社区模型选择仍关闭。

社区版默认免登录、本地 SQLite 和本机工具执行保持不变。点击桌面头像，在菜单中选择“连接服务器”：填写服务器根地址或完整 `/api/agent-bus/v1` 地址，匿名检测通过后进入现有密码登录和租户选择流程。服务端模式沿用已有业务页面；连接入口不代表全部业务能力已经联调通过。

仅保存最近一次服务器地址，每次启动仍进本地。连接后显示服务器地址，登录前后都能返回本地；返回会退出服务器会话、停止本机服务端 Agent 并重建 ProviderScope。本地定时任务随本地工作区卸载停止调度，返回时恢复；不增加后台双调度。连接失败保留地址输入和本地工作区。

连接弹窗底部左侧提供“接入指南”入口，使用系统浏览器打开固定的 GitHub README（`https://github.com/zbwork/zhiban-ai#readme`），保留当前弹窗及已输入地址；打开失败给出中文提示。

## 公共广场与头像菜单（2026-11-11）

头像菜单在本地显示“连接服务器”，在服务器工作区显示当前服务器及“返回本地”，两种模式均提供“接入指南”。侧栏不再单独重复连接操作；登录页保留返回入口。菜单先关闭，再使用宿主上下文打开弹窗或切换工作区，沿用现有会话清理流程。

服务器工作区的数字员工页保留当前服务器的个人、组织员工与原创建/聊天/编辑操作，另外展示独立公共员工目录。用户确认后可将模板名称、公开简介、人设及头像复制为当前服务器的个人员工，使用服务器配置的运行时；不复制内部描述、不自动装配技能/应用、不发送本地 Key。公共模板不直接作为当前服务器可执行员工，不直接把其 UUID 送入服务器聊天。技能页的公共广场独立使用现有匿名 `CommunitySkillCatalog`，当前服务器的技能和装配操作仍归服务器管理。公共目录请求不携带登录凭据，不随服务器地址切换；失败显示中文原因及重试，不静默伪装成空列表。

### 数字员工分类修正

桌面数字员工只保留原有“全部 / 官方 / 组织 / 我的”来源分类，取消额外的公共/服务器切换。全部合并公共模板和当前服务器可见员工；官方显示公共模板与服务器平台员工；组织和我的分别显示真实服务器组织员工和当前账号创建的个人员工。公共模板只提供“添加到当前服务器”，服务器员工继续使用原宿主的创建、聊天、编辑、删除流程；模板和服务器 UUID 即使碰巧相同也不得混用操作。搜索同时作用于两种目录。公共目录失败显示独立中文重试提示，不能遮挡组织/我的；服务器目录失败不妨碍已加载公共模板，也不能伪装成服务器没有员工。

调研来源：[Flutter 架构建议](https://docs.flutter.dev/app-architecture/recommendations)。行业做法是视图组合不同数据源，资源操作仍由各自数据源负责。当前已复用原画廊和业务宿主，但公共目录把组织/个人固定为空，导致可点击分类无数据。adapt 为单层来源筛选与显示层合并；adopt 保留原服务器业务宿主；reject 隐藏分类、把模板当成可执行服务器员工或复制一套 CRUD。

验收：默认全部可见模板、组织与个人；依次切换组织/我的/官方回读正确来源；个人保留编辑能力，组织只读，模板主按钮为添加；搜索过滤两种目录；任一数据源失败不掩盖另一来源，提示可重试。

调研来源：[Flutter 架构建议](https://docs.flutter.dev/app-architecture/recommendations)（依赖注入与数据源隔离）、[WAI-ARIA 菜单按钮](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/)（头像按钮打开操作菜单）。行业做法：公开目录与租户资源分别归属对应数据源；账户/工作区操作集中在身份菜单。当前已有匿名目录客户端、服务器 Provider 与头像菜单，adopt 复用这些实现；adapt 为目录请求独立、员工画廊按来源组合、技能保留独立视图；reject 给公共目录追加服务器 token、把公共员工 UUID 直接当服务器员工、用本地快照掩盖网络失败。

### 验收

- 公共与服务器技能共用紧凑页头，技能工作区切换器同标题一行；数字员工使用一组来源分类；员工和技能不显示常驻刷新按钮，失败保留重试。公共员工沿用原画廊的筛选/搜索行、卡片网格及详情样式，添加操作仍明确为复制到当前服务器。
- 本地头像菜单可打开原连接弹窗；服务器头像菜单显示真实地址、可返回本地；接入指南失败可反馈。
- 连接本机 Bus 后公共员工和技能仍来自公共目录，服务器成员及默认助手仍可见。
- 公共请求无 Authorization，当前服务器数据仍按账号/租户鉴权；断网显示可重试错误。
- 保留本地数据、连接代数隔离、登录页返回入口及既有服务器聊天/技能装配。

## 地址与检测契约

### 公共技能范围（2026-11-12）

公共技能只浏览目录和详情；撤销本轮为服务器新增的下载、导入与安装接口。当前服务器技能继续使用已有列表和装配流程。此范围替代此前公共技能直接安装方案。

- 接受 HTTPS；HTTP 仅允许 localhost、回环与 RFC1918 私网 IP，界面说明用于本机/局域网调试。拒绝用户信息、查询、片段、非 Bus 路径、无效端口及其他协议。反向代理须暴露固定 Bus 前缀。
- 使用独立 Dio、8 秒超时、禁止重定向、无认证头访问 `GET /api/agent-bus/v1/auth/captcha`，验证 HTTP 200、`success: true`、`data.captchaId` 与图片字段。检测仅证明登录接口形状匹配，不证明身份、IM、对象存储和模型可用；登录前可看到目标地址。
- 版本 `communityEdition` 与服务器连接状态分别管理；不翻转版本开关来开放商业专属接口。公共员工/技能市场地址保持独立。

## 会话和数据边界

### 当前会话已读（2026-11-11 修订）

桌面对话页首次自动恢复会话，必须在历史加载成功且该会话仍可见时，通过已有 Bus 已读接口持久化水位，同时清除本地和 IM 未读。不能只依赖路由首次进入时的回调：会话通常稍后才异步就绪。恢复前台、重新连接或刷新列表发现当前可见会话仍有未读时，也要补报；免打扰仅抑制通知，不阻止已读。其他会话、其他页面或后台收到的消息保留未读。标读进行中，旧列表响应不能使红点恢复；标读失败仍允许后续权威快照与重连重试。

采用既有“本地即时更新 + 服务端水位确认 + 刷新竞态保护”方案，复用统一标读方法；不以隐藏当前行或总数徽标替代服务端状态。验收包含：冷启动历史延迟、切换页面、切换会话、前台恢复、免打扰会话、标读与列表并发，以及真实 API/数据库水位。

切换时先卸载旧页面/Provider，停止旧运行，清除旧会话并清理 IM，关闭旧业务 Dio；请求与登录结果用连接代数拒绝过期写入，TokenRefresher 随连接重建。旧请求不能把 token 带到新地址或回写旧登录态。服务器地址只在清理完成后生效；失败停留可返回本地的错误页。每次连接都重新登录，不保存多服务器凭据。聊天缓存沿用 API 地址、环境、账号、租户分区。

本地库、技能、模型 Key 和用户工作目录不删除、不上传。社区版模型仍使用既有本地凭据范围，不自动同步给服务器。服务端模型由部署配置提供；远程 BYOK 同步、完整云端工具链、本地数据导入、多服务器账号保持及双向同步延后。客户端仅调用 Bus API，管理后台地址不从商业/开发环境推断。

## 行业最佳实践与 EasyO 适配性

调研来源：[Flutter 架构建议](https://docs.flutter.dev/app-architecture/recommendations)、[离线优先](https://docs.flutter.dev/app-architecture/design-patterns/offline-first)、[RFC8252](https://www.rfc-editor.org/rfc/rfc8252)。

行业做法：数据来源通过依赖注入分离；凭据绑定服务端；原生 OAuth 使用外部浏览器及 PKCE。当前已有独立本地工作区、Riverpod、Bus 会话路由。adopt 依赖注入与状态归属；adapt 为单一活动工作区，复用已有密码登录，先建立连接边界；defer OAuth 和全量 Repository 抽象，避免只为地址入口改写全部业务层；reject 自动把本地数据/Key 上传服务器及复用其他服务器 token。

### 2026-11-13 续期凭据修复

根因：scope/switch 返回新的 accessToken，但不旋转/返回 refreshToken；客户端通用保存逻辑误删旧 refreshToken，导致 access 到期后无凭据续期。切主体仅在旧/新 access 的 aid、sid 均存在且相同时保留当前 refreshToken；普通登录缺少 refreshToken 仍清旧值，禁止跨账号/会话复用。续期仍走原端点与撤销校验，不延长 access 时效或绕过鉴权。验收覆盖切租户后持久化、到期续期和重放、轮换 token、网络失败保留、无效 refresh 登出、切换工作区迟到响应不写入。真实联调只用独立成员账号与独立 bundle，不重启/登录管理员窗口。

## 里程碑二：管理台完整字段与权限（2026-11-13）

2026-11-18 验收范围：组织同步和智能体托管环境暂缓，本轮数字员工验证使用成员本机 DSH 和 Codex App Server。应用操作审计沿用现有事件队列和审计详情，记录认证请求的实际账号与执行角色：后台创建、编辑、删除和密钥轮换按后台作用域归属，客户端打开应用归属用户。角色与账号从经过认证的请求或已有启动入参取得，独立于应用资源的创建者，旧事件不回填。验收使用本机独立租户，实际编辑应用后从管理台审计页确认账号和角色。

用户知识库审计页面的查询曾因缺少社区 Admin 路由返回 404。恢复现有页面的查询端点，使用 `tenant.kb.read_user_private` 单独鉴权，权限种子限系统租户管理员。目标必须是当前租户有效成员，结果只包括该成员个人知识库的页面所需元数据。成功查询（包括 0 项）先写入操作者、目标和结果数，再返回结果。审计落库失败则返回错误。验收检查该页查询及审计详情，并验证普通成员和跨租户目标的拒绝。沿用逐请求授权、既有知识库和审计仓储。

### 2026-11-17 用户指定的三项收尾

仅先完成「系统管理/权限与角色」「凭证与接入/单点登录」「数字员工绑定应用」，均用本机独立租户和真实 UI 验收，不重复聊天与定时任务。

- 自定义角色：管理员显式分配了当前范围的管理权限后，应可进入对应范围的管理台；没有管理权限的普通成员仍不可进入。资格按当前 scope 计算，不把 A 租户权限带到 B；每个操作继续校验原 permission code。菜单及按钮按当前权限显示，直接输入 URL/API 仍由服务端拒绝。
- 单点登录：接通原 OIDC discovery、state/nonce 一次性校验、ID Token 签名及账号绑定。仅允许当前 IdP 租户已有的有效成员；首次邮箱匹配要求 IdP 明确 email_verified。SSO 会话绑定该 IdP 租户，刷新及切范围均不得扩张到平台或其他租户。不自动创建账号、授予角色或关闭证书验证。Admin Web 只调用 Admin 公共登录接口；桌面员工对话只调用 Bus。
- 数字员工应用（用户纠正）：应用绑定数字员工，在该员工对话中使用既有应用入口。不得新增客户端工作台 tab。后台绑定 → 对话能力栏加载 → 原 launch 换发单次授权码 → 原桌面应用面板展示，保留显示模式、关闭与返回，不向应用拼入用户登录 token。

行业依据：采用 [OWASP OAuth2](https://cheatsheetseries.owasp.org/cheatsheets/OAuth2_Cheat_Sheet.html) 的 state/nonce、固定回调与 token 验证，采用 [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) 的联邦身份绑定边界；适配为租户配置的认证仅产生该租户会话，不复用全平台登录权限。以官方 [Keycloak 容器](https://www.keycloak.org/server/containers) 在本机独立端口作为真实测试 IdP；不使用伪造签名或 mock token 验收。

验收：只读自定义角色登录可读部门、不可写/读其他模块、不可跨租户；撤权后刷新/重新登录拒绝。实际 Keycloak 登录到回跳进入正确租户，错误 state/重放/未绑定成员拒绝。后台将应用绑定到数字员工后，客户端该员工对话的应用入口可见并可点击，得到实际授权回跳结果；解绑或停用后刷新不再可用，关闭/返回对话正常。

员工绑定不能绕过租户应用启用开关：客户端目录与会话应用列表均读取当前租户设置；已有绑定保留以便重新启用，但停用应用不作为可启动入口输出，缓存旧入口调用 launch 也必须拒绝。读取设置失败须报错，不按启用处理；无设置行沿用原员工绑定默认启用语义。此处复用既有 tenant_app_settings，不新增工作台或第二套开关。OIDC state 同时绑定发起浏览器的 HttpOnly/SameSite Cookie 与服务端一次性 state，不能仅凭他人浏览器产生的回调登录。

### 本机群聊与协作验收

桌面在已连接的服务器工作区发送本机员工群聊文本时，用当前登录会话显式提供本机执行设备。仅本机可执行、已发布的活跃群成员进入候选。群聊继续通过同一 WuKong 时间线投递用户消息和员工结果，普通 IM 事件不授予设备执行权。管理台在群聊详情可应用同租户 Speaker 模板，先覆盖手动、主持人及轮询。轮询状态按群保存。消息、可见性、群成员权限保持各自原有边界。

本机员工间协作由正在运行的 DSH 或 Codex 通过任务能力实际发起。目标校验员工协作开关、准入规则及发起账号的员工可见性。仅转交明确的文字任务，协作信息与源任务绑定。管理员可以处理协作策略审批，批准后沿 Bus 调度回到原账号及设备会话。过期、撤销会话、成员和发布状态改变须在派发前拒绝，也不得借用审批人会话。请求使用单次审批，终态回写既有调用治理记录。社区版路径不引入服务端运行器。

行业做法采用交易级授权与执行前复核。适配到当前部署，运行能力由已鉴权的本机任务限定，审批与实际执行分离，权限变化导致失败。采用原 IM、设备 task 和审批状态机，拒绝仅凭账号找在线电脑、复用管理员凭据及直接跨租户转交。 [OWASP 交易授权](https://cheatsheetseries.owasp.org/cheatsheets/Transaction_Authorization_Cheat_Sheet.html)

实际 UI 验收使用独立租户与测试账号。普通群连续两条消息需要由不同本机引擎回复并与策略一致。实际协作请求须先显示待审批，管理台同意后目标员工才执行，桌面显示结果并回读调用状态。检查错误租户、离线设备、重复审批和重复派发。

同一群内按群会话与员工分别保存本机工作目录和权限，避免轮流响应时一个员工复用另一员工的工作环境。群详情的数字员工响应记录展示实际选中的员工及派发时使用的策略。提交协作请求属于协作操作，沿用本机授权并由管理员决定是否派发，无需声明文件交付。

### 里程碑二剩余验收

- 手动策略使用桌面已选择的结构化群成员身份。含空格的名字可被选中，未点名时只投递群消息。主持人策略按后台保存的群内主持人响应。
- 本机审批在原设备离线时拒绝同意并可在设备恢复时重试。过期请求进入已过期，不可派发给目标员工。每次成功批准仍只领取一次。
- 多步编排在社区版先复用已有顺序编排、步骤及调用治理记录。管理员配置本租户已发布的本机员工顺序。发起人从主控会话运行，逐步检查当前成员可见性、主控协作能力、目标准入及原桌面在线。两个步骤仅使用本机 DSH 和 Codex，前一步的实际文字结果作为后一步输入；失败及时结束，不切换执行设备。
- 编排每步查询主控和目标员工的当前配置。管理员在前一步期间撤回目标调用权限时，下一步记录准入拒绝并结束编排。
- 本机协作一旦被领取，调用记录与目标运行使用同一标识。Bus 可在重启或写入中断后从运行记录恢复终态。无法确认执行结果时记录中断并清除待交接正文，已领取的工作只执行一次。
- 真人群消息在没有可调度员工时照常投递。手动和主持人策略仅在目标可用时触发，轮询跳过当前成员不可调用的员工并保留群的原有轮询顺序。
- 桌面企业登录从已连接服务器的登录页发现现有身份提供方，经系统浏览器完成授权。只接受固定路径的回环回调，端口由客户端临时分配。Bus 复用 OIDC state、nonce、PKCE S256、一次性回调以及租户成员检查，客户端将同源登录结果交给既有会话存储。IdP 应为同一客户端登记原后台回调和桌面回环回调。管理台登录流程保留原回调。采用 [RFC 8252](https://datatracker.ietf.org/doc/html/rfc8252#section-7.3) 的外部浏览器和回环做法以及 [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636) 的代码校验。保留代码在服务器交换，不用 WebView 收取企业凭据，不将社区会话令牌返回浏览器。
- 使用独立账号从员工会话启动实际应用，在后台审计按同一应用和当前时间回读操作者账号以及用户角色，不复用旧创建或编辑事件。
