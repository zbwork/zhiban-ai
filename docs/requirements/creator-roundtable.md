# 博主圆桌需求与验收

## 1. 目标

社区版桌面端新增“博主圆桌”，把用户有权访问的公开作品或本人授权内容，在本机形成一条可追溯链路：

`渠道授权 / 单条链接 → 作品归档 → 逐字稿与证据 → 博主专家 → 圆桌问答 → 知识图谱与交付物`

本期以抖音为第一个渠道，桌面端直接使用现有模型服务配置，不新增后台，也不把登录态、原始媒体、逐字稿或知识资产上传到知办服务器。

## 2. 来源与边界

本需求以 `/Users/lemonliu/Downloads/知办AI-博主圆桌-v20-交付包` 的 PRD、58 张状态图和 5 个工作流 Skill 为输入。交付包中的 GitHub 博主头像仅标注为“内部 UI 视觉参考”，不得随社区版公开发布；添加博主入口接受单条抖音链接或含单个链接的完整分享文案，兼容复制过程中转义的 HTTPS 链接分隔符，保留用户输入供失败后编辑或重试。正式界面优先显示已同步的公开头像。抖音未返回缩略图时读取备用尺寸或同一作者的作品资料；缺失的数据不覆盖原头像。头像尚未加载或不可用时显示博主首字。

产品边界：

- 只处理用户主动提交、公开可访问或用户已授权访问的内容。
- 不绕过验证码、访问控制、付费限制或平台风控。
- 登录状态只保存在应用本机私有目录，不写入日志、数据库明文字段或模型提示词。
- 删除渠道授权时同时删除本地 Cookie/令牌；已生成知识资产是否删除由用户另行确认。
- 单条作品导入不要求授权整个账号；需要查看博主其他作品或批量同步时再引导授权。
- 默认只手动同步，不在后台自动抓取。

## 3. 行业做法与适配判断

| 主题 | 行业做法 | 知办AI 适配判断 | 采用方案 |
|---|---|---|---|
| 本地结构化数据 | Flutter 官方建议大量、可查询的本地数据使用 SQLite，并通过参数化条件避免注入 | 已有 `community_workspace_v1.db` 和版本迁移 | 复用现有数据库，新增博主、作品、证据、会话、任务、资产表；升级过程可回滚，禁止另建 JSON 真相源 |
| 长任务 | Flutter 官方建议将昂贵解析放到 isolate，避免阻塞界面 | 下载、抽帧、ASR、OCR 都是长任务 | UI 只提交任务；子进程/后台 isolate 执行；任务阶段持久化，可取消、失败后从已完成阶段续跑 |
| 媒体转写 | `whisper.cpp` 支持 macOS、Windows、Linux 和多种硬件后端 | 社区版需覆盖 Apple Silicon、Intel Mac、Windows x64 | 使用按需下载的 `whisper.cpp` 运行时和模型，不把大模型塞进安装包；先字幕、无字幕再 ASR |
| 受限站点登录 | `yt-dlp` 官方支持浏览器 Cookie，但明确提示 Cookie 文件包含敏感登录信息；站点反爬仍可能导致 403 | 不能把整浏览器 Cookie 库复制到应用 | 使用应用内授权会话或用户明确选择的本地 Cookie 导入；只保留目标域 Cookie；403 明确提示重新授权，不伪装成成功 |
| 对话起始建议 | Copilot 在会话起始页提供可选提示 | 圆桌可切换专家，建议需要跟随已选专家和已发布版本 | 从已发布方法取建议，点击填入草稿并选中对应专家，用户确认后发送 |
| 可追溯生成 | RAG/知识产品通常冻结模型、来源版本和引用 | 圆桌回答与交付物必须可复核 | 每轮问答/任务保存模型快照、专家版本、作品版本和证据锚点；无证据时明确标注“暂无依据” |

参考：

- [Microsoft Copilot Studio：对话起始建议](https://learn.microsoft.com/en-us/microsoft-copilot-studio/configure-starter-prompts)
- [Flutter：使用 SQLite 持久化数据](https://docs.flutter.dev/cookbook/persistence/sqlite)
- [Flutter：后台解析与 isolate](https://docs.flutter.dev/cookbook/networking/background-parsing)
- [`whisper.cpp` 官方仓库](https://github.com/ggml-org/whisper.cpp)
- [`yt-dlp` Cookie 与 403 说明](https://github.com/yt-dlp/yt-dlp/wiki/FAQ)

不采用：

- 不直接打包 Python、F2 或一套独立工具页作为正式产品交互。
- 不从用户默认浏览器静默读取全部 Cookie。
- 不依赖云端知办后台完成社区版本地数据处理。
- 不把原型中的固定 GPT/Claude 选项写死；模型来自现有“模型服务”。
- 不用演示假数据伪造已完成的同步、逐字稿、回答或交付物。

## 4. 信息架构

桌面端以 v20 交付包设计图为验收基准。博主详情按图 14 从上到下展示返回按钮、博主和同步卡，再呈现左侧作品列表、右侧作品与逐字稿。 作品列表以各作品的封面或首张图文图片作为行首缩略图，缺图或加载失败时显示平台标识。视频封面放在列表，详情展示播放和逐字稿；图文图片在详情仍可浏览。归档、转写和专家工具置于主内容之后。macOS 页头避开系统标题栏的双击区域，右上角复用社区版对话的模型按钮与弹层，支持搜索、按平台筛选、刷新列表及进入模型服务设置。圆桌独立保存选择，并与知识资产共用。未配置时，设置入口在标签行右侧。主页面保留「圆桌专家团」「知识资产」两个标签，标题和首个标签的图标对齐圆桌区域左侧的内容边线。作品与逐字稿通过右侧博主列表进入详情。使用交付包的空圆桌场景图、右侧列表、席位角标和底部提问条对齐初次进入画面。自动化用例覆盖标签切换、引导、添加入口与小窗布局，并在桌面运行截图复核。

1. **圆桌专家团**：展示席位、问答专家选择、模型选择、对话历史和引用。
2. **作品与逐字稿**：博主列表、作品列表、媒体预览、逐字稿和证据锚点。
3. **知识资产**：知识图谱、关联作品、电子书、离线网页和可下载 Skill。

展示席位最多 8 个，只影响画面。点击已就绪专家的席位名牌会切换该专家是否参与下一轮，不改变席位位置。 尚未发布专家 Skill 的席位以中性色标记「暂不可问」，点击名牌打开该博主详情，可查看蒸馏状态和继续入口。发布成功后名牌恢复可问状态。底部「选择专家」直接打开带头像的多选面板。按 PRD 图 06，整行可点击，选中行使用浅色高亮和右侧小勾，头像、姓名及勾选位按行对齐。可全选或清空已就绪专家，关闭后回到圆桌输入栏。面板标题栏使用 UiSheetHeader，关闭沿用其标准 32×32 图标按钮。 圆桌抽屉、引导、各类弹框、预览和对话的关闭使用 32×32 逻辑像素点击区、16 逻辑像素的中性关闭图标，并保留键盘与无障碍名称。鼠标悬停仅显示中性底色。全选和清空使用 28 逻辑像素高的紧凑文字按钮。全选和清空仅在可改变选择时启用。新对话默认选中全部已就绪专家。

圆桌场景按原图比例缩放，在主区域内水平和垂直居中，人物和名牌同步调整。悬浮对话和专家选择随场景底边定位。博主列表收起为右侧窄栏，依次显示展开、添加博主、配置渠道和可滚动的头像列表。按 PRD 图 03，展开与渠道设置使用无底色线框图标，添加使用 26 逻辑像素的蓝底白色加号。点击窄栏头像进入作品详情，返回恢复窄栏。通过展开的博主列表进入详情，返回恢复该列表。抽屉在「圆桌专家团」标签内容内从右侧滑入，遮罩只覆盖该标签内容，切换标签时收起。主图位置保持稳定。普通操作按钮使用 32 逻辑像素的最小高度，提问栏的输入框与专家选择、发送操作统一为 36 逻辑像素。提问栏贴在圆桌画面内的底边。模型选择器优先给模型名留出空间。展示席位按席位编号和本地博主标识保存，重开后恢复。移除某席时其他席位不移动，添加时使用第一个空席。设置席位不自动创建专家或选择问答参与人。 场景沿用 v20 交付的空圆桌。按实景示例逐席标定人物显示范围，近侧和两侧椅背、扶手使用同一张场景的原像素遮挡人物。靠近镜头的形象使用全身坐姿和朝桌视角，远侧使用至桌沿的坐姿上身。实际绘制仍随场景等比缩放。未生成形象时椅子留空，名牌照常显示。生成后只在对应席位叠加该博主的虚拟人物。

首次导入有公开头像的博主时分配一个空席。有可用的图片编辑模型时，按模型服务和模型在配置中的顺序，用第一个可用模型在后台生成该席位的虚拟形象。博主和作品保存可先完成。恢复旧席位、保存展示席位或启用图片模型后，也会检查该席位是否缺少形象。有缓存时直接回显，同一页面、同一模型配置的失败请求不会循环重试。因席位满、缺头像或没有可用图片模型而未能生成时，补齐条件后可在「展示席位」补生成。再次导入已有博主不改变席位。选择「在圆桌展示」分配席位后，有公开头像的博主可点击「生成形象」。已有形象时显示「重新生成」，弹窗默认选中第一个可用图片模型，用户可以改选后确认。缺少头像时说明原因。用户选择现有模型服务中能进行图片编辑的图片模型并确认后，客户端发送公开博主头像和该席视角说明，生成透明 PNG 的 AI 虚拟形象。保存到应用私有目录，以博主稳定标识、头像版本和席号分别缓存。只替换目标席位的人物图层；其他席位、会话和专家选择不受影响。失败保留之前的形象，并提示检查图片模型或重试。采用图片编辑接口的参考图能力，复用既有模型配置与逐席遮挡；不会使用对话文本模型代替图片生成，也不会把真实博主头像打进安装包。 [图像编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)

沿用「提供默认值，并允许用户修改」的交互做法。默认值只决定本次生成所用的图片模型。重生成可以单独改选，成功后替换该席位的旧图，失败时保留旧图。 [NN/G 默认值与用户控制](https://www.nngroup.com/articles/radio-buttons-default-selection/)

设置窗口逐行展示头像、名称及上席或取消按钮，完成时保存。首次引导根据当前抖音登录状态展示连接渠道或添加博主。 渠道弹窗使用交付稿的品牌图标与六行布局，仅抖音可授权。

## 5. 本地数据契约

稳定标识：

- `creator_id`：渠道 + 渠道用户稳定 ID 的散列，不用昵称作主键。
- `work_id`：渠道 + 渠道作品稳定 ID；同一作品重复导入必须幂等。
- `source_version`：作品正文、字幕或媒体内容变化后递增。
- `expert_id`：一个博主对应一个稳定专家；`expert_version` 每次成功发布递增。
- `evidence_id`：指向 `work_id + source_version + anchor`，锚点可为时间段、段落或图片序号。
- `conversation_id` / `turn_id`：圆桌会话与轮次稳定 ID。
- `job_id`：同步、蒸馏、生成任务稳定 ID。

任务必须冻结：

```text
job_id, actor_id, model_id, workflow_id, workflow_version,
creator_ids, source_versions, request_payload
```

任务阶段：

`validate → retrieve/evidence → structured candidates → program/evidence validation → render/store → publish`

重试沿用原任务和冻结快照，保留已通过阶段；只有最终校验通过的版本可以成为当前发布版本。

专家任务每完成一批复核，即保存已消费的证据条数、批次数和累计通过的方法。专家更新通过版本等价复核后保存合并结果及对照发布版本。图谱失败后复用该结果；如果对照版本已变化，重新对照当前发布版本。用户在博主详情重试时沿用原任务编号、模型和证据快照，跳过已复核批次。模型停用时保留检查点，可重新启用原模型或另起任务重新生成。

资产通过复核后保存渲染检查点。若生成、复核或写文件失败，或应用退出，重新打开同类资产的生成窗口可继续上一次任务。复核前继续使用原任务、原名称、原模型和原专家版本生成并复核内容。 结构和引用检查通过即保存候选稿。复核服务中断时只复核原候选稿，明确拒绝后才重新生成。已有复核检查点时只执行本机渲染和发布。原模型停用或原专家版本无法读取时，保留任务供恢复。重新发起生成按当前表单及模型执行。

## 6. 功能要求

### 6.1 渠道与作品

- 允许粘贴抖音短链或完整链接，解析出作品、博主和原始链接。
- 首次读取抖音作品时，客户端按 macOS Apple Silicon、macOS Intel 和 Windows x64 自动准备私有解析环境，并展示下载与准备进度。同一环境的并发读取共用准备任务，成功后复用。准备失败保留链接，重试可继续使用已通过校验的下载。用户无需安装 Python、uv 或配置 PATH。
- 添加前核对作品范围。确认时按当前模型尝试完成专家蒸馏，表单明确说明会向所选模型发送已选博主的证据。处理可转后台，结果分别显示作品入库、证据是否足够和专家是否发布。证据不足或未选模型时保留作品，用户可以打开详情继续。渠道读取失败保留原链接，支持修改或重试。
- 添加博主的确认弹窗随预览内容收紧。简介或作品较多时预览区独立滚动，底部保留处理说明和确认按钮。
- 已选模型时，添加博主的确认按钮为「开始蒸馏」，随后自动归档、准备证据并发布专家。没有选模型时可先归档作品。详情页优先展示专家当前状态，缺少可引用的逐字稿或图文证据时显示「待补充作品」。博主详情在同步卡下显示专家状态。未发布专家且已有待转写的归档媒体时，提供「补齐逐字稿并蒸馏」。该入口在本机补齐逐字稿，再用所选文本模型和新增证据蒸馏；证据未增加时显示原因，保留原任务供重试。已有可用证据时可继续生成或更新专家。原任务重试仍沿用其证据快照。
- 导入反馈区分保存资料、下载原片或图文媒体、转写、分析与专家发布。只保存作品记录时提示后续动作，下载或转写失败在最终结果中保留。打开作品详情可依据已存文件和逐字稿查看状态。
- 需要批量同步或查看其他作品时，使用应用内授权流程；授权结果明确显示成功、失效或需重新授权。
- 授权依次展示用途、抖音扫码、范围确认、完成。只有抖音网页完成真实登录并返回有效登录标识，才可进入范围确认；已失效会话须取得新的登录标识。授权确认使用本机浏览器会话，范围为公开博主资料和可读作品。完成回到原渠道设置、原添加链接或原同步范围，用户确认后再执行原操作。
- 同步范围支持“全部作品”与“最新 N 条”，本期只允许手动触发。最新 N 条直接按剩余条数请求博主最近作品，按作品 ID 去重，取足即停。置顶作品参与最终的发布时间排序，单独出现时不占正常发布时间顺序的名额，避免旧置顶挤掉新作品。若返回不足，只补剩余条数。续传沿用已核对的作品。
- 同步分页使用已归档的抖音作者稳定标识，按页校验作者、游标和授权。当前次完整取得所选范围后，在单个本地事务中落库并报告新增数量。渠道失败或取消时保留已归档内容。 第一页核对完整作者资料。后续非空页逐条核验作品作者或联合作品的参与者，沿用已核对的作者资料。遇到空页时仍单独核对作者资料。 渠道确认的联合作品在多位参与博主的作品列表中共用同一归档、逐字稿和证据标识。每位博主新增关联时计为该博主新增作品。
- 同步每验证一页就保存续传进度。网络中断、取消或应用退出后，重新打开同步弹窗可按原范围、原模型继续，从未完成的页读取；修改范围后启动新任务。进度只保存稳定标识、发布时间、游标和页数。入库前按作品标识重新读取需要的媒体详情。作品入库和同步完成状态在同一事务提交。
- 导入及手动同步先保存作品记录，再流式归档适配器返回的直链 MP4。仅连接 HTTPS 媒体域名，每次重定向重新校验，不携带登录 Cookie，不持久化带有效期的媒体地址。原片按 256 MiB 上限流式归档和转写，并校验作品版本。25 MiB 上限只适用于内嵌预览，超过时用本机播放器打开。包含该抖音作品实测返回的媒体主机 v5-dy-ov-experiment.zjcdn.com。媒体失败保留作品，显示未归档数，下一次同步可补齐。已有媒体文件正常时直接复用。[Dio 流式响应](https://pub.dev/packages/dio#response-stream) · [Dart 重定向控制](https://api.dart.dev/dart-io/HttpClientRequest/followRedirects.html)
- 渠道提供 VTT 或 SRT 时，优先读取中文字幕，校验长度和时间码后保存为可引用的逐字稿。已有逐字稿保留；渠道字幕读取失败单独反馈，仍保留视频和作品，可再同步。
- 图文按原始图片顺序下载到本机，逐张限制为 10 MiB 和 2400 万像素。先读取图片编码尺寸，控制解码内存。原图序号和地址同时匹配时才复用已存文件，归档不改变作品证据版本。预览和 OCR 优先读取本机副本，副本缺失时可读取原图。同步失败保留已保存的作品和图片，可再次同步补齐。[Flutter 图片编码读取](https://api.flutter.dev/flutter/dart-ui/ImageDescriptor/encoded.html)
- 保存渠道给出的图文正文，详情按原有换行展示。段落证据记录作品版本和段落序号，在图片不可用时仍可阅读和引用正文。现存图文在再次导入后补齐正文。
- 图文详情按图 16 展示标题、原文要点和正文。要点卡由正文中带标题的原段落直接呈现，最多三项。开放正文和图片保留原顺序；引用定位到任一要点时，仍使用原段落序号和作者原文。
- 授权说明、确认范围和成功用同一紧凑弹窗，保留四步进度。扫码步骤优先保证真实抖音网页可读，在当前窗口中展开。
- 无登录状态或渠道明确报告登录失效时，在同步弹窗内提供重新连接入口。关闭渠道设置后保留原同步范围，用户再次点击开始同步才发起请求。限流、网络故障和无法确认原因的 403 继续显示对应错误。抖音 HTTP 502、503、504 提示服务暂不可用。同步保留最后一个已验证的游标，供用户重试。全部作品在成功响应明确标记结束时停止分页。最新 N 条也在作品不足且渠道确认没有更多时结束。
- 作品详情的同步卡保留最近一次成功时间。同步范围弹窗在提交并通过登录检查后切换为进度视图，显示当前阶段、已核对页数、去重后的已扫描作品数与最终新增数。限量同步同时显示目标条数。全部作品总量未知时显示实际计数。可在弹窗内取消或关闭后继续，详情卡的「查看进度」重开同一任务，作品保存后继续显示媒体归档的作品序号、转写及知识更新，完成时保留各阶段结果。 同步卡和进度弹窗只显示转写结果，省略底层组件安装提示。同步期间可以浏览、切换已归档作品，或返回圆桌再打开详情。同一博主不能重复同步。提交本地事务期间暂时禁用取消。取消、失败及重新授权入口在同步卡反馈，重新打开同步范围时恢复原参数。离开博主圆桌模块时停止采集，保留已读页供下次续传。
- 手动同步先提交作品及媒体结果。可引用证据变化后，使用发起同步时选中的模型独立更新专家和图谱。页面分别显示作品新增数量、证据准备和知识任务结果。知识任务失败时保留作品与上一发布版本，按原任务、原模型、原证据和检查点重试，不重复抓取渠道。没有可用证据时提示补充，模型不可用时保留作品，允许切换模型重新提交。 其他专家正在处理时，知识更新按入队顺序处理，保存原模型和证据，当前任务结束后自动继续。重新进入圆桌时恢复尚未开始的队列。
- 视频优先使用平台字幕，无字幕时本机 ASR；图文保留正文与图片顺序；音频走本机 ASR。 导入或同步归档视频后，自动读取内嵌字幕，仍无字幕则使用本机 Whisper 转写。首次需要时，应用自动下载并校验对应平台的转写组件及默认多语种模型，缓存到应用数据目录。 Whisper Base 多语种模型优先从 Hugging Face 国内镜像获取，镜像不可用或校验失败时切换官方源。两处文件共用同一 SHA-256 校验值；下载报告网络、超时、体积和校验错误。手动转写与后台导入、同步使用同一流程，下载时展示当前组件和百分比。网络或校验失败、无音轨或转写失败时保留视频，并显示可重试的原因。作品详情把手动归档、转写和导入字幕收在「补充资料」中，作为自动取证失败后的补充入口。已有逐字稿跳过自动处理。 当前 macOS 语音识别组件要求 Apple Silicon 使用 macOS 13.0 及以上，Intel 使用 macOS 13.3 及以上。较旧系统仍可读取已有字幕或导入字幕文件。
- 为已有本地字幕提供手动导入 SRT/VTT 的入口。解析起止毫秒、保留逐段文字，保存时校验作品版本；导入的字幕来源要与平台字幕、ASR 区分。
- 用户自行选择作品的本地媒体时，优先提取文字字幕。没有可用字幕时，本机调用应用管理的 FFmpeg 和 whisper.cpp，将结果标为 ASR。平台字幕或导入的字幕文件可直接使用。
- 作品详情可归档用户选择的 MP4、MOV 视频和 M4A 音频，并在现有文件预览中播放。参照 Flutter 官方的本地媒体和按需初始化做法，复用现有跨平台 WebView 播放控件，按 256 MiB 上限流式归档。超过 25 MiB 时提供本机播放器入口。M4A 以音频元素加载并复用播放、定位和音量操作。加载失败时在窄播放器中仍可滚动查看说明与重试。归档保留原始文件字节，校验作品版本后持久化。原文件移动后仍能播放，也可直接对归档副本转写。媒体保存在应用私有目录，旧版引用继续读取原有字幕快照。[Flutter 本地视频播放](https://docs.flutter.dev/cookbook/plugins/play-video)
- macOS 图文详情可对用户选中的单张渠道图片运行系统 Vision OCR。图片仅从已知抖音图片 CDN 读取，使用资源体积和像素上限，识别结果关联作品版本与图片序号。专家、对话和资产顺序引用图片原文及序号，图文地址变化后旧版引用仍保留冻结文本。[Apple Vision 文字识别](https://developer.apple.com/documentation/vision/recognizing-text-in-images)
- 作品详情必须能回到来源页，并显示同步时间、处理状态、原始链接、逐字稿与证据定位。 作品列表标注媒介类型，高亮正在查看的作品，初次进入时高亮默认作品。已有时标的逐字稿按原始起始时间分行，旧版纯文本逐字稿仍原样显示。逐字稿正文最多高 360 逻辑像素，小窗口按可视高度调整，超出部分在卡片内独立滚动。 视频和音频在当前作品详情内播放。「播放视频／播放音频」和「逐字稿」使用互斥的分段选中态，默认显示逐字稿，选中态始终跟随实际显示的内容。切换作品移除原播放器，缺少媒体时保留原地址与逐字稿入口。

### 6.2 专家 Skill

- 每位博主只有一个稳定专家 Skill，可有多个版本。
- 人设至少包含外在表达、核心立场、方法、能力、交付物和边界。 冻结公开作者资料。工作原则、能力、交付物和领域边界直接由复核过的方法和可定位引用生成。使用公开头像作为专家身份标识，缺少时使用中性形象。资料无依据的外貌描述和个人表达习惯留空。
- 每个方法和重要判断必须关联证据；至少一个方法通过证据校验后才允许启用专家。
- 蒸馏按带时标证据分批运行。候选步骤先检查引用是否属于该批证据，再通过单独的模型请求复核文字能否支撑动作。只发布逐步通过的完整方法，版本中冻结原文与时标。本机模型服务配置为远程地址时，蒸馏按钮需告知会把选中博主的字幕片段发送给所选模型服务。
- 新版本失败时继续使用旧发布版本，不覆盖可用版本。
- 问题、适用条件、边界及步骤一致的方法沿用已发布的方法标识，按步骤合并当前证据集合里的引用。专家更新时，先匹配文字相同的方法。对尚未匹配且步骤数相同的少量候选，由本次选定的模型独立核对目标、适用条件、停止边界及同顺序步骤是否等价。仅接受当前候选中的一对一结论，条件不同或判断不明确时保留独立方法。确认等价的方法沿用旧图谱主题标识，成员引用刷新为这一版可定位的证据。来源已改版时，旧引用仍在旧发布版本中可追溯。
- 已发布专家可下载对应版本的技能包，包含调用说明 `SKILL.md`、方法库 `methods.json`、证据索引 `evidence.json` 和版本清单 `manifest.json`。下载使用当时冻结的证据，后续同步不会改变旧产物。

### 6.3 圆桌问答

- 一轮可选择多个专家；每位专家独立给出有引用的观点，之后生成综合结论。
- 单独的问候和询问身份由所选专家在本机回复，明确身份是基于公开作品整理的 AI 专家。问候后附带实际问题时，继续走作品检索和引用校验。两类回复都保留在同一会话。
- 新对话及上一轮只有无引用回复时展示建议问题，最多 4 条，优先让各位已选专家各占一条。建议来自所选专家已发布版本的方法。 建议卡片使用主题蓝色的浅色底和细边框，宽屏两列等宽等高，窄屏单列。卡片显示专家名称和至多两行问题。点击后将问题填入空输入框，并选中对应专家，用户可编辑后发送。
- 每位专家只答自己版本的证据。单个回答的引文必须在发送给该专家的来源中，综合观点只引用本轮通过校验的来源。回答落库时保存引用原文及时间段。
- 每轮冻结模型和专家版本；历史轮次不随后续同步改写。
- 支持完整、悬浮、收起三种展示；支持新建、切换和删除会话。 收起后从输入栏可以直接打开全屏。 打开悬浮或全屏对话后，输入框可用时自动获得焦点，可直接键入内容。悬浮或全屏均可直接收回输入栏，重新打开时保留本轮专家选择、会话和草稿。 悬浮对话在圆桌画面下方水平居中，按场景大小扩大阅读区，打开时由对话输入栏替代画面上的提问入口。消息沿用主对话页的浅蓝、浅灰气泡样式，专家名和头像放在气泡外。对话展开和收起使用 260 毫秒过渡，系统启用减少动态效果时立即切换。展开时在同一页面显示历史侧栏，悬浮对话通过标题处的通用单选下拉切换会话，宽度最多 176 逻辑像素，下拉与标题控件同宽，选项区随内容收紧并支持滚动。专家选择位于输入栏。按 PRD 图 18 至图 20，收起、悬浮和全屏共用浅色底与深色文字的专家入口，左侧预览最多 3 位已选专家的头像，右侧显示实际人数。未选择时显示「选择专家」。消息按提问与各位专家回复分组显示。收起、悬浮和全屏共用标准单行输入组件，输入框和专家选择按钮高 36 逻辑像素，文字和占位提示垂直居中。输入框、专家选择与常规操作统一用 10 逻辑像素圆角，输入框和专家选择使用同一描边色，输入栏相邻控件间距为 8 逻辑像素。对话的新建、关闭、放大、退出全屏、收起、历史列表和删除操作共用弹框关闭按钮的 UiIconButton。点击区为 32×32 逻辑像素，图标为 16 逻辑像素，统一使用中性色和悬停反馈，在各行内垂直居中，支持键盘聚焦与激活。文字按钮宽度由文案决定。按 PRD 图 18，悬浮对话的会话选择器使用浅灰描边和深色文字，标题栏上下留白，新对话按钮紧邻选择器。悬浮对话发送按钮采用 30 逻辑像素的蓝色圆面和白色向右发送箭头，禁用时显示灰色圆面。
- 回答气泡下方用紧凑文字按钮显示引用数量。展开后以较小字号显示出处、原文和归档入口。回答必须能展开来源作品和锚点；无可靠证据时明确标注，不允许编造引用。 归档回看按作品 ID、版本、时标或段落显示历史原文。全屏历史按对话标题或消息内容查找，可以从列表删除单项，删除当前对话后打开相邻对话并保留其草稿。

- 提交后立即清空输入框，在消息区显示本轮问题和专家正在回答的状态。成功后显示保存的本轮消息；提交未保存时恢复原草稿，用户可重新发送。消息较少时从顶部按发送顺序排列。消息超出可视范围后可滚动，打开、切换对话及发送时显示最新消息。放大对话并收起侧栏后，仍可通过标题查看最近对话。
- 参照主对话页用正向滚动区排列消息，并在布局后定位到最新消息。等待提示只显示在界面，问题、回复和引用仍一起保存。

### 6.4 知识图谱与资产

- 三类资产共用来源选择表单，显示选中数量与交付格式。生成中单独显示处理阶段，失败保留表单并提供重试。已有通过复核的草稿优先按原任务恢复。

- 图谱默认网络视图，支持拖拽、缩放 50%–300%、复位和全屏。 画布节点保留设计稿的小色点。长标签最多显示两行，悬停查看全文。节点按归属分层，同一方法的条件和边界相邻，父节点对齐分支中线。结构关系在列间走折线。作品节点保持可点，选中方法或作品后才显示相关引用线，跨列引用从卡片上方绕行。选中项和相关连线高亮。主题与作品筛选使用统一控件，缩放、复位和全屏共用画布左下角工具条。
- 借鉴 Dify 同层分支留出独立空间和 React Flow 布局方案中 ELK 的分层、端口及折线布线。社区版图谱的主结构由博主、主题、方法和条件构成，使用现有 Flutter 画布做确定性排布。作品引用是跨层的多对多关系，通过按选中项显示来控制交叉。 [Dify 工作流源码](https://github.com/langgenius/dify/blob/main/api/core/workflow/generator/runner.py) · [React Flow 布局](https://reactflow.dev/learn/layouting/layouting) · [ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)
- 网络与散点从同一发布版本绘制节点。散点按类型分布，隐藏关系线；网络和散点使用下划线页签，切换视图和全屏共用图谱状态及画布变换。参照 Flutter 的交互画布做法，用同一变换控制器承接拖动、滚轮、按钮缩放和复位。[Flutter InteractiveViewer](https://api.flutter.dev/flutter/widgets/InteractiveViewer-class.html)
- 采用与作品证据可追溯的模型聚类。专家任务仅对新增或改动的方法提议主题，复用其他已发布版本中的主题标识，并校验每条归类确实引用该方法当前版本的原文。主题、成员及其证据与专家同事务发布；失败时继续显示旧版。同义主题复用稳定标识，语义不同或条件冲突的方法分开。历史专家的结构图可继续查看，更新后纳入语义主题。[GraphRAG 索引数据流](https://microsoft.github.io/graphrag/index/default_dataflow/) · [W3C 来源模型](https://www.w3.org/TR/prov-dm/)
- 「全部博主」视图聚合主题，展开属于该主题的不同作者及其方法；作品回跳使用该条证据所属的博主、作品和来源版本。已有按博主查看的结构图继续使用同一版本证据。
- 在单博主和跨博主视图中，将已复核的方法条件和约束显示为独立节点。归属、主题、适用和支持等关系使用同一发布版本的证据。选择关联线时展示支持该条线的证据，选择条件时展示所属方法的证据。方法与条件保留各自标识，多博主共享主题时仍分别展示各自的条件。
- 前置关系须来自两个方法共同引用的同一段证据。模型提出方法端点及原文片段，客户端校验顺序标记、片段顺序、方法对应性、重复及环路。关系随专家版本保存，点击有向线只显示支持该关系的原文。已有且未变更的关系可复用。
- 主题命名保留共同业务目标和核心做法。示例数值、触发情境和验收条件保留在原方法中；明确互斥的适用条件单独归类。 归类时同时比较已发布主题中的适用条件、停止边界和代表性操作。提交前明确提示该规则摘要参与模型归类，已发布作品的逐字稿仍留在本地。批次中任一方法缺少合法归类时保留旧发布版本，待补齐后再发布。
- 节点和边都能回到证据；支持按博主/作品/主题筛选。
- 专家技能包同时交付 `graph.json`，从该专家版本冻结的方法、主题、前置关系和证据生成。包含版本、节点、边、来源引用和计数，所有关系引用必须可达。旧发布版本可从原数据生成结构图，缺失的主题和顺序关系自然为空。
- 作品和主题筛选可同时使用。主题匹配方法名称及适用条件；作品筛选保留对应的已验证引用。选中节点仍在筛选结果中时保留，关联作品通过卡片标题展开或收起。展开时按条展示时间戳或位置、摘录和查看入口，正文超过可用高度后在卡片内滚动。
- 从图谱证据可打开本机归档的对应作品，并看到专家发布时引用的原文与时间段。关闭作品详情后保留图谱筛选、缩放和所选节点。当前作品版本更新时，明确显示引用来自历史版本。
- 电子书输出 PDF，网页输出单文件离线 HTML，任务 Skill 输出包含 `SKILL.md` 的压缩包。
- 离线网页「检查清单」使用有标签的原生复选框，支持鼠标和键盘。生成时要求每行是一项操作，每项继承区块的证据链接。清单在应用内隔离预览可勾选。在浏览器打开本机文件时，在浏览器支持本地存储的情况下，按成品清单保存进度。隔离预览无法存储时仍可在当前页面勾选。模板只内嵌维护进度的固定脚本，模型文字全部转义，不访问网络。
- 图 25 至 27 的同类成品列表按生成时间倒序展示，卡片显示本类总数与最近两项。完整列表沿用卡片中的查看和下载入口，关闭预览后仍留在该类型列表。
- 技能预览从已保存的 ZIP 读取 `SKILL.md`，按生成规格中的标题提供章节目录、上一节、下一节和阅读缩放。换节同步目录选中项和节号，缩放保留当前章节。预览内可下载同一份 ZIP，旧成品缺少结构化标题时仍提供全文阅读。
- 电子书与离线网页在应用内复用文件预览，预览打开本机成品并校验格式与大小。关闭预览后回到原资产列表。网页预览的「新窗口打开」将同一份本机 HTML 交给系统默认浏览器。 电子书把封面、各章节和来源索引写成 PDF 书签。PDF 文件包含来源索引的目录链接，章节引用可从支持 PDF 链接的阅读器跳到对应来源条目。共用预览从 PDF 读取本地书签，提供目录跳转并随翻页更新当前章节。缩放保持当前页，首尾页禁用对应翻页。已有无书签 PDF 继续使用原预览。 [PDF.js 文档](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFDocumentProxy.html)
- 生成前校验输入和模型；生成后校验结构、引用、文件可打开性。失败时不提供半成品下载。 资产生成按名称优先召回已选专家的相关方法和已验证引用。用中文相邻字和字母数字词匹配方法主题、适用条件、操作和证据，优先将相关候选放进已有上下文额度。资料无明确词面匹配时，模型可判断证据是否足以成稿。明确证据不足时提示补充来源或调整名称，不保存草稿。
- 采用 Dart PDF 库与现有中文字体在本机生成 PDF；网页使用转义后的静态模板，压缩包仅包含程序生成的固定路径。模型输出只作为结构化内容，不作为 HTML、路径或脚本执行。[Dart PDF 文档](https://pub.dev/packages/pdf/versions/3.11.3)

### 6.5 共用模型

- 圆桌、专家蒸馏和知识资产共用一个模块级模型选择。
- 选项来自本机“模型服务”已启用模型；密钥继续由现有私有凭据存储管理。
- 模型不可用时禁止开始新任务；历史任务显示原模型快照，不自动换模型重跑。

## 7. 分阶段交付

### M1：真实单条链路

- 导航、页面骨架和模块级模型选择。
- 单条链接导入、真实作品/博主信息、本地持久化。
- 视频/音频逐字稿与证据锚点。
- 一位博主生成一个可启用的专家 Skill。
- 单专家问答能引用原作品。

### M2：批量与圆桌

- 授权状态、手动批量同步、去重和版本。
- 多专家圆桌、展示席位、对话历史与删除。
- 失败任务按阶段恢复。

### M3：知识资产

- 可交互知识图谱。
- PDF、离线 HTML、Skill 压缩包生成、查看与下载。

## 8. 验收矩阵

每项必须使用社区版桌面程序和真实本地数据验证；单元测试不能替代 UI 验收。

| 场景 | 必须看到的结果 |
|---|---|
| 未配置模型 | 页面显示“配置模型服务”，生成/问答按钮不可用 |
| 导入同一链接两次 | 只保留一个 `work_id`，第二次更新检查时间，不重复建作品 |
| 无字幕视频 | 本机 ASR 生成带时间锚点逐字稿，UI 在处理时不卡死 |
| 授权失效 | 显示重新授权；旧作品和已发布专家仍可查看 |
| 专家生成失败 | 失败版本可重试，旧发布版本仍能问答 |
| 圆桌回答 | 每个事实性结论可打开至少一个来源锚点；无依据项明确提示 |
| 切换模型 | 新任务使用新模型；历史任务仍显示旧快照 |
| 退出重开 | 博主、作品、逐字稿、会话、任务与资产仍在 |
| 删除授权 | 本地目标域 Cookie/令牌被删除，日志和数据库不含密钥 |
| 生成资产失败 | 不出现可下载半成品；重试沿用原任务快照 |
| Windows / macOS | 两个平台均能完成 M1；运行时缺失时提供可理解的安装/下载提示 |

## 9. 本轮非目标

- 自动定时采集、移动端、云端同步、团队共享和后台管理。
- 对未授权私密内容、付费内容或受平台限制内容进行绕过访问。
- 完整音频事件识别；本期只要求语音转写和与画面/文本联合分析。
- 将大型 ASR 模型直接塞入 DMG/EXE。
