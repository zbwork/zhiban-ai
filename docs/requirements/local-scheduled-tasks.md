# 社区版本地定时任务

复用原 TaskPage、卡片、历史、TaskEditorDialog/TaskEditorContent；仅替换数据与回调。不初始化远端员工、会话、模板 Provider，不请求产品私有 API。仅使用自定义提示词和员工本地对话。导航开放自动任务，页面说明关闭期间不执行，重开到期任务合并补执行一次。

SQLite v7 保存定义、下一次时间、运行快照、终态，升级保留原数据。支持新建、编辑、暂停/恢复、删除、立即执行，删除后历史保留。单次保存完整年月日，开始执行即禁用，失败/中断不自动重试。本机时区五字段 cron 支持数字、通配、列表、范围、步进，周日 0/7，日与星期同时受限取或。无效规则或无未来时间拒绝保存。

调度随工作区启动，不依赖页面。事务认领并推进时间后执行，同任务/员工不重入，员工忙保留到期状态。恢复每任务只补一次。退出撤销请求；重启未完成记录标记 interrupted，不重复认领过的单次任务。执行完成只回写状态，不恢复被编辑/暂停/删除的旧定义。

沿用员工当前模型、Key、目录、技能、权限和原工具确认弹框，完全访问不落盘、重启降级不变。结果存原会话，历史可打开对应员工。失败/停止如实记录，不在任务历史保存 Key 或原始异常。

## 行业最佳实践与 EasyO 适配性

- 调研来源：[APScheduler 用户指南](https://apscheduler.readthedocs.io/en/stable/userguide.html#missed-job-executions-and-coalescing)，已在线读取持久化、coalescing、max_instances 原则。
- 行业做法：定义和运行分离、合并漏跑、限制并发。
- 当前上下文：单机 Flutter/SQLite，已有执行器和审批，无常驻服务。
- 适配判断：adopt 持久化、先认领、快照；adapt 每员工串行、漏跑合并、本机时区。
- 采用方案：本地 Service + 客户端计时，复用聊天执行器。
- 不采用项：defer 关闭后唤醒/跨时区；reject 私有 API、持久化完全访问、自动批准、重试中断任务。

## 验收矩阵

1. 无 token 原界面 CRUD/暂停/恢复/立即执行，远端目录和模板零请求。
2. 单次完整时间回显，cron/月末/星期正确。
3. 重启保留，到期补一次，重复 tick/员工忙不重入。
4. 真实成功/失败/中断记录，删除后历史保留，会话打开正确员工。
5. 复用模型、工具审批和停止，默认服务端行为保留。


## Review 修复契约（2026-11-05）

Cron 日期/星期中包含通配步进时采用两字段匹配结果的交集，不能省略步进字段过滤；两字段均显式限制时仍取或。验收覆盖日期 */2、星期 */2、步进与显式星期组合、两字段同时步进及原显式日期/星期 OR。

定时任务须在认领前同步取得与聊天、删除员工共用的员工执行令牌；令牌持有到任务执行及终态回写结束。取锁失败时不写认领、不禁用单次、不推进下次时间。认领失败/任务已删/数据库异常必须释放，停止和退出取消同一令牌。验收在认领数据库等待期间发起普通聊天，验证聊天不能抢占；反向员工被聊天占用时，任务维持待执行状态，结束后仅执行一次。

适配判断：沿用已调研的 max_instances 原则，adopt 把并发限制置于所有入口共用的控制层；reject 只在定时任务内部加锁和失败后恢复单次任务（执行副作用状态可能未知）。
