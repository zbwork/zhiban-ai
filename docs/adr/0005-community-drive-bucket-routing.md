# 社区云盘的租户存储桶

日期 2026-11-18

社区部署已有一个固定的对象存储地址和凭据。让部署者用 `COMMUNITY_DRIVE_BUCKET_ALLOWLIST` 按租户批准同一存储服务内可用于新写入的桶，格式为 `租户数字 ID=桶名`，多条用逗号分隔。租户管理员可用专属云盘表单保存桶名，清除配置后新文件回到部署默认桶。来自后台的任意 Endpoint、区域或凭据仍仅用于连接探测，无法接管实际读写。

S3 的对象身份包含桶和对象键。采用在已有数据库对象键中记录专属桶位置，物理对象键保持原格式。单次上传的临时键与最终键同时固定到同一桶，签名、分片、确认、回收和旧版本清理都沿用这一位置。无前缀的历史记录走原部署桶。空间内或跨空间移动在租户范围内保留来源桶。数据库无需新增列或搬迁旧对象。[S3 对象键](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-keys.html)

按部署批准范围选择写入桶，持久化位置读取仍绑定部署地址与凭据，并核对键内租户。这样移除允许写入的桶或清除配置时已有文件仍可读。部署者需保留历史桶，以及用于读取这些桶的连接地址和权限。暂缓跨对象存储服务和历史数据搬迁，避免租户表单将文件发送至任意网络地址。[OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

启用前先升级 Admin、Bus 与 Worker。已有专属桶位置后，旧版本无法定位这些对象，停用时清除写入配置并保留新版的读取能力。

激活专属桶前用部署凭据探测桶是否可访问。保存失败时保留原配置。验收在独立本地租户用两个真实 MinIO 桶完成。以实际文件字节验证保存前上传、保存后新上传、刷新后历史下载、清除后新上传，以及切换期间已签发上传的确认。按租户检验实际读写与分片路径。
