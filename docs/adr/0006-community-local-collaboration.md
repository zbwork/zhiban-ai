# 社区版在原桌面设备执行群聊与协作

日期 2026-11-18

连接服务器工作区时，群消息继续使用 WuKong 时间线。Bus 用带登录会话的桌面发送请求校验发起成员、群成员及设备，再使用该群配置选出响应员工。普通 IM 回调没有桌面执行授权。轮询进度跟随群配置，本机工作目录则按群与员工分别确定，避免两名员工共用本机授权。

本机员工从正在执行的任务提交文字协作，Bus 检查发起能力、目标准入规则和当前成员可见性。审批用现有的租户后台。新增的持久化队列保存源运行标识与待交接文字，Admin 同意时入队，Bus 领取后再核对原账号、租户、登录会话、设备及员工权限。领取过的请求不自动重发，避免执行有副作用的任务两次。运行结果进入目标员工对话，调用状态回写现有治理页。

采用逐笔授权和执行前的最终复核。复用现有审批及本机任务通道，Admin 和 Bus 通过数据库交接，使后台操作人的会话不参与任务执行。首版支持一次文字转交和一层执行，群内本机执行支持手动、主持人和轮询。沿用社区版追加迁移，部署时先应用迁移 30，再升级 Admin、Bus、管理台和桌面运行器。[OWASP 交易授权](https://cheatsheetseries.owasp.org/cheatsheets/Transaction_Authorization_Cheat_Sheet.html)

## 顺序编排

在社区版接回已有编排执行器和 PostgreSQL 步骤记录。管理员在本机员工的运行配置中选择 2 到 8 个已发布的本机员工及顺序。发起时校验完整步骤与桌面设备，通过已有 A2A 能力、目标白名单、用户可见性和配额逐步派发。每步调用普通本机任务接口，取已完成的可读文本传递给下一步。步骤失败时结束顺序执行，同一步不自动重跑。租户治理页记录员工、步骤及状态，正文沿已有成员会话展示。

每步从库中刷新主控和目标员工，再执行现有准入校验。协作恢复复用本机运行记录。目标运行以调用 UUID 标识，创建运行和恢复结案都锁定同一领取记录。领取超过观察窗口后，恢复过程按目标运行的终态结案。仍可完成的运行等到硬截止时间，缺少运行记录或已到截止时间的未完成运行以中断结案。旧记录也能按中断结案。普通群消息对成员资格校验后即可投递，员工可见性和群聊能力用于筛选响应对象。
