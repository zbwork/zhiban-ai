# ADR-0007：博主圆桌采用本地可恢复知识流水线

- 状态：已采用
- 日期：2026-11-25
- 关联需求：[博主圆桌需求与验收](../requirements/creator-roundtable.md)

## 背景

博主圆桌同时涉及渠道授权、媒体下载、字幕/ASR/OCR、模型蒸馏、引用问答和文件生成。社区版要求完全本机运行，并已具备本地 SQLite、模型服务和私有凭据文件。把这些步骤塞进一个页面回调会导致界面卡死、退出丢进度、失败后无法判断是否需要重复抓取或重复生成。

## 决策

### 1. 复用现有社区数据库

在 `community_workspace_v1.db` 中以版本迁移新增博主圆桌表。SQLite 保存结构化数据和任务状态；媒体、逐字稿附件、图像、PDF、HTML、Skill 包保存到应用支持目录，数据库只存相对路径、散列和元数据。

不新增第二个 JSON/SQLite 真相源，避免同一博主在聊天和圆桌模块出现两套生命周期。

联合作品用带外键的博主与作品关联表表示。升级时从原有归属补齐关系，保留作品 ID、媒体和引用。关联与作品在同步的同一事务提交。重复存储作品会分叉逐字稿和引用，因此沿用一条作品记录。见 [SQLite 外键](https://www.sqlite.org/foreignkeys.html)及[事务](https://www.sqlite.org/lang_transaction.html)。

### 2. 任务是持久化状态机

导入、同步、专家生成和资产生成都建本地任务，冻结模型与来源版本。每个阶段完成后在同一事务中写入阶段输出和状态；应用重启后把仍在运行的任务标为“已中断，可继续”，不自动从头重跑。 作品同步后的知识更新把原模型、作者资料和证据保存为 SQLite 中的待执行专家任务，和手动蒸馏串行处理。已开始的任务沿用中断和手动重试规则，尚未开始的任务在圆桌应用可运行时继续，不使用仅驻内存的队列。

抖音同步的分页进度保存原范围、模型、已校验的游标及作品标识和发布时间。恢复时用当前有效登录状态续读，已完成页只补取最终选中作品的详情，不把临时媒体地址写入任务进度。

### 3. 运行时按需安装

- 媒体探测、抽帧和转码使用最小 FFmpeg 运行时。
- 语音转写使用 `whisper.cpp`；应用首次需要时自动准备固定版本的转写组件和默认多语种模型，通过 SHA-256 校验后写入应用目录。归档视频保留在本机，下载只获取组件和模型。FFmpeg 取自 imageio-ffmpeg 发布包，Whisper 的 Windows CPU 包取自上游发布，macOS 包取自独立构建项目，模型取自上游模型仓库的固定提交。CLI 单独运行，应用不依赖系统包管理器或 shell 配置。 模型约 148 MB，使用 [Hugging Face 镜像](https://hf-mirror.com/) 优先服务国内网络，并保留固定提交的官方源。两处下载校验同一 SHA-256，避免为接入镜像而替换模型或改变识别质量。
- 渠道解析器是可替换适配器。抖音适配器沿用 F2，首次调用通过同一 Dart 下载器按平台获取固定版本的 uv，并校验压缩包摘要。使用 [uv 管理的 Python](https://docs.astral.sh/uv/concepts/python-versions/) 和其内置校验清单，在应用数据目录创建固定 CPython 补丁版本的独立环境，再从固定提交安装并校验 F2，成功导入模块后标记就绪。当前渠道解析需要解释器，随应用按需准备可复用现有适配器并避免使用系统 Python 或系统包管理器。
- 运行时必须校验版本和文件散列，安装目录不可写入凭据。

这样避免将 ASR 模型和完整 Python 环境打入安装包，也为 Windows x64、Intel Mac 和 Apple Silicon 分别选择合适二进制。

### 4. 凭据与内容分离

渠道 Cookie/令牌沿用社区版私有凭据文件的安全边界，按渠道和本地身份分区；数据库只保存授权状态、过期时间和凭据引用。子进程通过 stdin 或权限受控的临时文件接收所需目标域 Cookie，禁止放入命令行、环境变量和日志。

### 5. 证据优先

每条知识方法、圆桌观点和交付物引用都指向固定的 `work_id + source_version + anchor`。检索结果只作为候选，发布前必须校验引用仍存在。专家新版本或资产校验失败时不替换当前发布版本。

### 6. UI 复用

主导航和模型选择复用现有桌面结构与模型服务；不新增独立工具页。所有处理状态来自真实任务记录。无模型、无授权、无作品、处理中、失败、可重试、已完成分别显示，不使用演示数据填充成功状态。

## 备选方案

### 直接把原型 HTML 放进 WebView

拒绝。它不能复用 Flutter 的模型、凭据、路由和本地数据库，且容易把样例数据误当真实状态。

### 所有处理都交给远端服务

拒绝。与社区版纯本机目标冲突，也会扩大用户登录态和媒体内容的数据外发范围。

### 把 F2/yt-dlp 直接当领域模型

拒绝。站点适配器变化频繁，且不同工具返回结构不同。它们只能实现渠道适配接口，不能成为 UI 和数据库契约。

## 影响

- 优点：本机隐私边界清楚、失败可恢复、历史可复核、跨平台运行时可独立升级。
- 成本：需要数据库迁移、任务状态机、运行时安装器和端到端 UI 验收。
- 风险：渠道页面或风控变化会使适配器失效；界面必须把“需要重新授权/暂不支持”如实呈现，不能回退到抓取绕过。
