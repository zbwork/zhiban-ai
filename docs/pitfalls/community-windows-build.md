# Windows 社区版构建

- CMake 配置测试会创建占位源码；runner 增加源文件后，测试夹具也必须同步。例如 desktop_network_bridge.cpp 已在实际源码中，但旧夹具未创建它，导致配置测试假失败。不可通过删除生产构建源文件修复。
- 构建机 C 盘空间不足时用独立短路径目录，复用经摘要校验的依赖缓存；不得重置已有工作区。
- AppContainer 自检需要交互会话；SSH 进程环境与交互用户环境不同。构建使用独立手动计划任务，安装验收另外使用普通权限，不能把构建自检等同于安装通过。
- 社区导出必须包含打包脚本的传递依赖。Windows bundler 调用 scripts/build-codex-windows.py，遗漏会在构建时失败；同时导出缓存信任检查测试，保留源码、补丁、工具链和二进制摘要校验。
- OS相对路径与接口路径不混用：Windows path.relative返回反斜杠，不能直接进入拒绝反斜杠的公共参数校验。仅转换可信OS计算结果，保留用户输入限制。
- Windows原生ACL只能作用于现有对象；必须显式保护尚未存在的持久化目录，不能从deny列表过滤掉。所有缺失路径必须在已授权可写根内，创建后固定句柄，撤销唯一SID后仅清理空目录。
- 不能仅将新包与构建机当前Release目录比体积：它可能已经包含同一冗余。必须直接读取用户原安装器内容。Windows使用native/codex兼容版时，npm平台vendor仍会随npm ci产生；打包前只保留实际执行的变体，保留版本/许可元数据并重新进行真实Codex测试。

- 2026-11-17 1.0.1：Windows 继承 PUB_HOSTED_URL=pub.flutter-io.cn，而源码 lock 的 registry 是 pub.dev。普通 pub get 因来源变化重新解析，发现与 Mac 相差 17 个版本；不能把同一源码归档等同为相同依赖。最终候选保留 Mac lock 的全部版本与 sha256，只适配镜像 URL，并用 --enforce-lockfile 校验后构建；不放宽 TLS/哈希。旧候选仅保留诊断，不交付。

- 2026-11-17 1.0.1：真实引擎 Shell 集成夹具给 Windows 完整隔离命令仅 10 秒，首轮 30 项中 9 个执行模式失败，单独模式 10/60 秒对照分别失败/通过，独立加载诊断钩子抓到原始 `local.command_timeout`（timeoutMs=10000）；直接工具探针含相同可读依赖树和私有目录保护时耗时 5.2–9.8 秒。测试等待预算应覆盖实际隔离启动/清理成本：Windows 使用生产工具已有默认值 60 秒，Mac 保持 10 秒，外层 120 秒/协议等待 100 秒继续有界；不得减少 ACL/deny 范围、跳过 Shell 或删除文件落盘断言。遵循原 Windows README 的 `--test-concurrency=1`，分别记录原始失败与最终结果；没有将此夹具修正说成产品隔离实现的性能修复。

- 2026-11-17 1.0.1：超时修正后的 Windows 包内回归曾 29/30 通过，`codex-missing-response-id` 在 2.45 秒终态 `zap.upstream_failure`；这不是此前 10 秒 Shell 超时。同一最终包独立连跑该场景 3 次全部通过，原失败没有原始引擎诊断，根因未确认，不得宣称修复；不自动重放用户的失败轮次。本轮只打包当前代码，后续完整复测结果单独写入发布记录。
