# 里程碑二：开源管理台到客户端闭环

用户目标：后台可配置开源版数字员工（DSH / Codex App Server）、租户及其余开源管理能力，并在真实 UI 验证。前置里程碑一已完成，不干扰用户登录与既有租户数据。

## 实施与保留

1. 复现真实管理台阻断，建立当前路由、权限、表依赖及写操作清单。
2. 复用已有后台 UI 与原服务，修复导出缺漏；权限保留原权限码、scope 与逐请求校验，禁止客户端直调 Admin。
3. 优先打通独立账号登录、平台/租户概览、租户创建/修改、成员/部门/角色与员工创建/编辑/发布。
4. 员工类型、运行位置及 DSH/Codex 选择沿原契约，保留原本机权限与模型配置边界；使用实际客户端验证可见与执行。
5. 再按已导出开源模块检查技能、应用、知识库、云盘、定时任务、审计等界面；商业依赖及尚未提供能力必须明确列出，不能用隐藏菜单或返回假数据完成验收。

数据库仅新增可追踪的追加迁移，复用原正式定义；不重写已执行迁移、不改迁移账本、不清库。修复依据先同步 requirements/server-workspace 与 architecture/community-schema-reuse。

## UI 验收矩阵

| 场景 | 验收证据 |
| --- | --- |
| 独立测试管理员 | 原生浏览器账号密码表单登录；不复用用户客户端账号 |
| 租户管理 | UI 创建、编辑、重新打开回读并进入测试租户 |
| 员工 DSH / Codex | UI 创建与发布两个本地员工，字段回读、客户端实际对话/文件结果 |
| 组织及权限 | UI 部门、成员与角色读写，普通成员/跨租户负向检查 |
| 其他开源模块 | 逐页入口 + 至少对应业务写入/回读；不能仅以 HTTP 200 算通过 |

验证：Go 定向 test/vet、管理台 lint/build、相关 Flutter 测试；真实本机管理台及独立 macOS 测试客户端。2026-11-16～17 已完成租户、部门、成员首次改密、职位、角色读写、DSH/Codex 员工发布与本机执行、头像全链路、组织技能包和知识文档等核心闭环。截图与脱敏证据已转存 docs，不只保留 /tmp；敏感夹具只放 ignored .local。

完整里程碑尚未宣布全部通过：SSO 桌面端入口扩展、组织同步及部分只读页面的业务写入未完成；本轮选定的角色委派登录、管理台 OIDC 与员工应用实际打开已验证；PG 词法检索和旧偶发执行失败的限制仍保留。逐项结论见[里程碑二验收记录](../verification/community-admin-milestone2-2026-11-17.md)，不得继续重复已通过的聊天/任务取代后台剩余验收。

用户明确要求完成剩余后台功能并逐项 UI 验证，不再重复测会话与任务。

1. 补自定义管理角色登录资格及菜单/按钮权限反馈，独立只读账号 UI 验收。
2. 装配原 OIDC 登录，补租户绑定与首次账号匹配保护，以真实本机 Keycloak 验证配置和回跳。

4. 保留默认本地模式、现有密码登录/首次改密、逐请求权限、租户隔离及用户自身会话。定向 Go test/vet、Admin lint/build、Dart 分析/回归及上述三条实际 UI 链路。
